The problem, and the answer

From copy-and-paste to one command

Teams have spent months making Scripture videos by hand, copying and pasting verses one at a time into a video editor. VIDX takes your USFM text and one audio file per chapter, works out when each verse is spoken, and renders a subtitled video for every chapter, ready for YouTube.

Timings from your audio

Forced alignment (--align) finds where each verse or phrase is spoken. It runs on your own computer. Timing files from Scripture App Builder are optional; use them if you already have them.

Section headings

Headings marked \s in the USFM are detected, timed as their own segments, and shown in their own style.

Subtitled chapter videos

Background video or image, music, your logo, and a chapter title. Landscape, vertical or square. Complex scripts are shaped correctly.

Fast rendering

GPU encoding (NVIDIA, Intel or AMD) is detected automatically, and several chapters can render at once.

Upload to YouTube

Titles, descriptions, tags and playlists are filled in from templates. If the daily limit is reached, it carries on the next day from where it stopped.

Subtitle files too

Need only captions? VIDX can write .srt and .ass files without rendering any video.

For the technical person on your team

Install

VIDX is a command-line program. Installing it, FFmpeg and your fonts is a one-time job. Writing the configuration for a new project takes a few hours to a day, depending on the settings.

  1. Download VIDX

    Get vidx.exe from the latest release. It is a single file with nothing to unpack. Put it in your project folder, open PowerShell there, and check it runs:

    .\vidx.exe --version

  2. Install FFmpeg separately

    vidx.exe does not include FFmpeg. You need FFmpeg 4.3 or newer, built with libass and HarfBuzz, and the ffmpeg command must be on your PATH. VIDX draws the subtitles through libass, and HarfBuzz shapes complex scripts.

    To check that your FFmpeg has both, run this. You should see --enable-libass and --enable-libharfbuzz:

    ffmpeg -hide_banner -buildconf | Select-String "libass|libharfbuzz"

  3. Install the fonts for your script

    Every font you name in the configuration must be installed on the computer that renders the videos. If text shows up as empty boxes, the font is missing or its name is misspelled.

  4. Download the alignment model (automatic, once)

    The first time you use --align, VIDX downloads a speech model of about 340 MB to %USERPROFILE%\.vidx\mms-aligner\ (~/.vidx/mms-aligner/). After that, alignment works offline. Your audio never leaves your computer.

  5. Optional: YouTube upload

    Automatic upload needs a free Google Cloud OAuth key, saved as %USERPROFILE%\.vidx\client_secrets.json. The publishing guide walks through it step by step. Without the key, VIDX still prepares a folder for each chapter with the video and a ready-to-paste metadata.txt, so you can upload by hand in YouTube Studio.

Quick start

One book, start to finish

This example makes videos for the Gospel of Mark. Lay the project out like this. The book's USFM can be a single file, and VIDX picks out each chapter itself.

my-project\
  vidx.exe
  mark.yaml            # the configuration, below
  mark\
    42MRK.SFM          # USFM for the whole book
    audio\01.mp3 ... 16.mp3
    bg.mp4             # background video loop (or a .jpg / .png)
    logo.png

1. Generate the timings

One chapter at a time. Because the audio is in a folder called audio, VIDX writes mark\timing\MRK-01-timing.txt beside it. Pass your language's ISO 639-3 code with --lang, which improves accuracy.

.\vidx.exe --align --usfm mark\42MRK.SFM --audio mark\audio\01.mp3 --lang mal

All 16 chapters in one go (PowerShell):

1..16 | ForEach-Object {
  $ch = "{0:d2}" -f $_
  .\vidx.exe --align --usfm mark\42MRK.SFM --audio "mark\audio\$ch.mp3" --lang mal -y
}

VIDX reads the chapter number from the first number in the audio filename. That works for 01.mp3, but not for names like B02___01_Mark.mp3. For those, add --chapter 1. Add --level phrase to get phrase-level timings (1a, 1b ...). If the narrator doesn't read the section headings aloud, add --no-headings. Already have SAB timing files? Skip this step and point the jobs at those files instead.

2. Write the configuration

Save this as mark.yaml. Paths are relative to the folder you run VIDX from. Add one job per chapter.

project:
  name: "Gospel of Mark"
  output_dir: "output/mark"
  language: "Malayalam"              # fills {language} in YouTube titles
  text_copyright: "© Your Bible Society"
  audio_copyright: "© Your Recording Studio"

video:
  resolution: "1920x1080"            # "1080x1920" vertical, "1080x1080" square
  background_media: "mark/bg.mp4"
  scaling_mode: "crop"
  loop_crossfade_sec: 1.0            # smooth the seam where the loop repeats
  watermark:
    image: "mark/logo.png"
    position: "top-right"
    scale: 0.08                      # 8% of the video width
    opacity: 0.75

style:
  verse:
    font: "Noto Sans Malayalam"      # must be installed
    size: 64
  heading:
    font: "Noto Sans Malayalam"
    size: 56
    hold_seconds: 20                 # keep each heading up into its section

publishing:
  privacy_status: "unlisted"
  playlist_name: "Gospel of Mark"
  title_template: "{h} {ch} - {language} Audio Bible"

jobs:
  - usfm: "mark/42MRK.SFM"
    timing: "mark/timing/MRK-01-timing.txt"
    audio: "mark/audio/01.mp3"
    output: "output/mark/Mark_01.mp4"
  - usfm: "mark/42MRK.SFM"
    timing: "mark/timing/MRK-02-timing.txt"
    audio: "mark/audio/02.mp3"
    output: "output/mark/Mark_02.mp4"
  # ... and so on to chapter 16

3. Check, then render

# Check the text quickly: subtitles only, no video
.\vidx.exe -c mark.yaml --generate-only --format srt

# Check the look: 15 seconds of each chapter (saved as Mark_01_15s.mp4 ...)
.\vidx.exe -c mark.yaml -t 15 -y

# The full book: GPU encoding, 4 chapters at a time
.\vidx.exe -c mark.yaml --gpu -y -w 4

-y answers yes to the one-time question about scaling a large (e.g. 4K) background down to 1080p. The finished videos are written to output\mark\.

4. Publish (optional)

Each render writes publish_manifest.json and a YouTube_Upload_Package folder into the output folder. To upload automatically:

.\vidx.exe -c mark.yaml --manifest output\mark\publish_manifest.json

A browser window asks you to sign in and choose the channel. If YouTube's daily limit stops the upload, run the same command the next day and it picks up where it stopped. Nothing is uploaded twice.

Fine-tuning a timing

A timing file is also an Audacity label track. Export it, drag the boundaries against the waveform, then merge the changes back:

.\vidx.exe --timing mark\timing\MRK-01-timing.txt --to-labels labels.txt
# Audacity: File > Import > Labels ... adjust ... File > Export > Export Labels
.\vidx.exe --timing mark\timing\MRK-01-timing.txt --from-labels labels.txt

Honest limits

What to know before you start

  • Windows only, for now. VIDX is a Windows program. There is no Mac or Linux version yet.
  • Command line, and someone technical to set it up. There are no windows or buttons yet. Someone comfortable with PowerShell needs to write the configuration file for each project. After that, a run is a single command. A simpler interface is planned, but there is no date yet.
  • YouTube's daily limit. Google's standard quota allows only a handful of automatic uploads a day. A whole book takes several days to upload. VIDX resumes each day, but it can't go faster than the quota allows.
  • Full-chapter videos only. Each video is one whole chapter. Short clips of single passages aren't supported yet.
  • Timings may need a nudge. If a recording opens with a spoken chapter announcement, verse 1 may start late. You can fix it in Audacity in a minute.

Known issues

Where the guides are wrong

Some of the longer guides don't match how VIDX actually behaves. The settings on this page are correct. Until the guides are fixed, trust this page over them.

  • The sample settings in the Getting Started guide are partly wrong. Use alignment, not position, for headings. Use a word such as "top-right" for the watermark position, not a number. Give opacity as a value from 0 to 1, such as 0.5, not 50. #23
  • The configuration guide's title_card setting does nothing. Use title_image instead. The guide also says publishing.enabled turns on uploading, but it doesn't. Uploads happen only when you run --publish or --manifest, and --manifest needs the path to publish_manifest.json. #24
  • The README says the .exe can't make timings. It can. --align works in vidx.exe. #22
  • Some guides and messages say to run pip install vidx[...]. You can ignore these. vidx.exe already includes everything it needs. #21
